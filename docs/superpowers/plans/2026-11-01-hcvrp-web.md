# Interfaz web HCVRP (plan 3 de 3) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dejar la app lista para que el cliente pruebe todas las funciones de la spec §6 en un navegador, servida por el mismo proceso FastAPI, más las mejoras pendientes de la API.

**Architecture:** SPA en `web/` (Vite + React + TypeScript + MapLibre) que compila a `web/dist`; FastAPI sirve ese directorio y deja `/api/*` intacto. Navegación por hash, sin router. El estado del plan se obtiene sondeando `GET /api/plan`.

**Tech Stack:** React 18, TypeScript 5, Vite 5, maplibre-gl 4, vitest, @fontsource/barlow y barlow-condensed. Teselas sin clave: `https://tiles.openfreemap.org/styles/liberty`.

**Spec:** `docs/superpowers/specs/2026-10-30-hcvrp-laguna-design.md` (§2 flujo, §5.1 ubicaciones, §6 pantallas, §8 comparación, §9 anti-objetivos).

## Global Constraints

- Todo texto visible en español, en lenguaje de quien planea (camión, viaje, recarga), nunca de sistema.
- Las reglas de negocio siguen solo en el motor; la web no recalcula costos, capacidad ni jornada.
- Hora mostrada = 09:00 + minuto. Jornada mostrada desde `params.shift_minutes`.
- Plan con clientes sin verificar: aviso visible siempre (anti-objetivo §9). Con proveedor `haversine`: aviso de distancias aproximadas.
- Plan desactualizado: visible como tal mientras llega el nuevo (§6.2).
- Responsive hasta móvil, foco de teclado visible, `prefers-reduced-motion` respetado.
- Colores: tinta `#17324D`, fondo `#EEF1F2`, superficie `#FFFFFF`, señal `#F2C200`; camiones V1 `#0E7C86`, V2 `#B26A00`, V3 `#6D3FA8`, V4 `#C2324E` (otros: `#3F6B3A`).
- Datos reales nunca en git: `web/dist` y `web/node_modules` van a `.gitignore`.

## Review Focus

1. Sesión vencida a mitad de uso (401 en cualquier llamada): vuelve al login sin perder la fecha elegida.
2. Error de la API al capturar (kg inválidos, 409, 422): el mensaje de `detail` se ve junto al formulario y los datos no se pierden.
3. Plan en `error` con plan anterior: se ve el mensaje y el plan viejo marcado como desactualizado.
4. Día sin pedidos con plan anterior: la pantalla Plan invita a capturar pedidos y no presenta el plan viejo como vigente.
5. Cliente sin ubicación con pedido: aparece en "pasa al día siguiente" con su motivo y se puede fijar en el mapa desde Clientes.

### Task 1: Mejoras de la API y servir la web

**Files:** Modify `src/hcvrp/api/{auth,routes_auth,planning,routes_plan,settings,app}.py`, `.gitignore`. Create `src/hcvrp/api/routes_web.py`, `README.md`. Test `tests/api/test_web.py`, `tests/api/test_auth.py`, `tests/api/test_planning.py`.

**Interfaces — Produces:**
- `GET /api/config` (con sesión) → `{"depot": {"lat","lon"}, "provider": str, "bounds": [lat_min, lat_max, lon_min, lon_max]}`.
- `Settings.web_dist: Path = Path("web/dist")`, env `HCVRP_WEB_DIST`.
- `inputs_hash(problem, provider: str = "")`: incluye el proveedor; `Recalculator` y `GET /api/plan` pasan `settings.provider`.

- Mensajes de bloqueo con el cliente: `el pedido '12'` → `el pedido de <nombre>`; motivo con `REASONS_ES`; `bloqueo infeasible` → `bloqueo imposible`.

### Task 3: Pantallas

**Files:** Create `web/src/{main.tsx,App.tsx,styles.css}`, `web/src/screens/{Login,Orders,Clients,Fleet,Plan}.tsx`, `web/src/components/{RouteMap,ShiftTimeline,TruckSheet}.tsx`.

- **Marco:** barra con selector de fecha (por defecto mañana), pestañas Pedidos, Plan, Clientes, Flota y parámetros, y estado del plan siempre visible.
- **Pedidos (§6.1):** buscador por código o nombre + kg; editar, borrar; cargar escenario de prueba; total de kg.
- **Clientes (§5.1):** lista con estado de ubicación + mapa; alta, edición, baja; clic en el mapa o arrastrar el punto fija la ubicación como verificada; filtro "sin verificar".
- **Flota y parámetros:** capacidad, rendimiento, disponibilidad; diésel, carga, jornada, entrega, recarga, viajes, límite de cálculo. Botón "Guardar cambios".
- **Plan:** avisos; resumen; carga de esta tarde; línea de la jornada; mapa con color por camión y viaje punteado desde el 2.º; tabla camión → viaje → paradas con horas, km, kg, %; fijar pedido a camión + viaje y quitar el bloqueo, con diferencia de costo; pasa al día siguiente con motivo; comparación contra línea base; botón Recalcular.
- **Hoja imprimible:** "Imprimir hoja" por camión con `@media print`, solo esa hoja.

- [ ] **Step 1:** Implementar. **Step 2:** `npm run build` sin errores de tipos. Commit `feat(web): pantallas de pedidos, plan, clientes y flota`.
